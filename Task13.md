# Task 13

## Что изменили

В проекте добавили сохранение state machine текущей задачи в файл, чтобы можно было продолжить работу после прерывания сессии.

### 1. Состояние workflow

Для текущей задачи теперь сохраняется отдельный файл:

- `generated/users/<userId>/current_task.json`

В нём хранится состояние этапов:

- `PLANNING`
- `EXECUTION`
- `VALIDATION`
- `DONE`

А также:

- текущий шаг и общее количество шагов;
- план задачи;
- уже выполненные пункты;
- текущий активный пункт.

### 2. Результаты общения между агентами

В `current_task.json` теперь дополнительно сохраняются промежуточные результаты работы агентов:

- результат текущего этапа;
- замечания валидации;
- запрос на доработку;
- количество попыток валидации;
- передачи управления между агентами.

Это позволяет не терять внутренний прогресс workflow, даже если сессия оборвалась между этапами.

### 3. Восстановление после прерывания

При новом сообщении пользователя state machine читает последнее сохранённое состояние из файла и продолжает работу с него.

Если задача была завершена, новый диалог запускает новый цикл планирования.  
Если задача была на этапе исполнения или валидации, сохранённые данные позволяют продолжить её без потери внутреннего контекста.

### 4. Сохранение после каждого шага

Состояние теперь записывается в файл не только в конце ответа пользователю, но и после каждого важного действия:

- после сообщения пользователя;
- после ответа каждого субагента;
- после перехода между стадиями.

За счёт этого `current_task.json` содержит актуальный снимок workflow почти в реальном времени.

## Как это сочетается с остальной памятью

В проекте теперь используются разные файлы памяти по назначению:

- `generated/users/<userId>/history.json` — история диалога;
- `context_source/users/<userId>/profile.md` — долговременный профиль пользователя;
- `context_source/users/<userId>/task_context.md` — рабочий контекст текущей задачи;
- `generated/users/<userId>/current_task.json` — состояние state machine и внутренний прогресс агентов.

## Итог

Теперь система хранит не только историю сообщений, но и внутреннее состояние выполнения задачи.

Это даёт возможность:

- продолжать задачу между сессиями;
- не терять этап, на котором остановились агенты;
- восстанавливать промежуточные результаты planning/execution/validation;
- держать workflow в отдельном техническом файле, не смешивая его с `history.json` и `profile.md`.
